## User story

As a Parent, I want the quiz my child plays to stay the curated school bank, so signing in does not add a second set of questions into Nursery.

Persona: Parent.

## Components

- `krushnatkhawale/study-shield` — mobile
- `krushnatkhawale/study-shield-backend`

## Technical context

`TrialContentDownloader.ensureTrialContent` still runs from `AuthViewModel` and POSTs a hardcoded bank with `className` `Trial`. `AcademicCatalogResolver.ordinalForClassName` maps `trial` to ordinal 2, the same ordinal as Nursery, and `QuestionBankLoader.load` appends any new text onto that freemium quiz. `QuestionController` create, bulk, load, update, and delete have no admin role. `SecurityConfig` only requires an authenticated user. `CatalogStartupSeeder` already pre-seeds the curated bands, so the mobile seed is no longer how the bank is filled.

## Acceptance

1. Success: A parent login does not call `POST /api/v1/questions/load`. A parent token receives 403 on question create, bulk create, load, update, and delete. An admin token can still load. The Nursery freemium question texts are unchanged after a parent login.
2. Failure: A parent token that still sends the trial bank gets 403, and the quiz question count does not change. The TV bundle stays the curated set.

## API / data contract impact

`POST /api/v1/questions`, `POST /api/v1/questions/bulk`, `POST /api/v1/questions/load`, `PUT /api/v1/questions/{id}`, and `DELETE /api/v1/questions/{id}` require role ADMIN. Parent mobile stops calling `/api/v1/questions/load`. `POST /api/v1/quiz-bundles` stays available to a signed-in parent.

## Testing requirements

Sign in as a parent and assert no question-load request is sent. Call load, create, and delete with a parent token and assert 403 and an unchanged question count. Call load with an admin token and assert the existing skip-duplicates behavior. Issue a Nursery bundle before and after the parent login and assert the question texts match.
