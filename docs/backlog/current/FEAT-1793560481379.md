## User story

As Engineering, I want a production boot to refuse a schema drift instead of altering or cloning tables, so a deploy cannot split the family's quizzes across `public` and `ss-prod`.

Persona: Engineering.

## Components

- `krushnatkhawale/study-shield-backend`

## Technical context

`application.yml` sets `spring.jpa.hibernate.ddl-auto` to `update`. The prod profile sets `hibernate.default_schema` to `"ss-prod"`, and `sql/schema.sql` creates `ss-dev` and `ss-prod`. No entity `@Table` pins a schema. The debt note says Hibernate still clones tables into `public` when the schema is not pinned, and `ddl-auto: update` will alter the live schema on boot.

## Acceptance

1. Success: The prod profile boots with `ddl-auto` `validate`. Entity tables stay in `"ss-prod"` (and in `"ss-dev"` on the default profile). A boot does not create those tables in `public`.
2. Failure: An entity field with no column fails startup and leaves the existing `ss-prod` rows unchanged. The app does not create a `public` copy to get past the error.

## API / data contract impact

None

## Testing requirements

Boot the prod profile against a database that already has the `ss-prod` tables. Assert `information_schema` shows no new `public` copies of entity tables. Add a temporary entity field with no column and assert startup fails without writing that column or a `public` table. Keep the regression profile on `create-drop`.
