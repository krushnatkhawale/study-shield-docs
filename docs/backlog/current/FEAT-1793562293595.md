## User story

As an Operator, I want the admin app to open without changing the product database, so a console boot cannot create or alter tables beside the backend.

Persona: Operator.

## Components

- `krushnatkhawale/study-shield-backend-admin`

## Technical context

`application.yml` sets `spring.jpa.hibernate.ddl-auto` to `update` and defaults `DATABASE_URL` to `jdbc:postgresql://localhost:5432/studyshield`. `ApplicationSettings` is an `@Entity` on `application_settings` with no schema. H2 is on the runtime classpath for the LAN/demo fallback. `SecurityConfiguration` permits `/h2-console/**` and ignores CSRF on that path. Tests already use an in-memory H2 URL.

## Acceptance

1. Success: A boot against the product Postgres does not CREATE or ALTER `application_settings`. `/h2-console` is not available on that boot. The LAN/demo fallback can still use its own H2 file, and the test suite still uses in-memory H2.
2. Failure: If the product database refuses the connection, the app does not switch to a file H2 and report a healthy boot. No request can open the H2 console against the product database.

## API / data contract impact

None

## Testing requirements

Boot the admin app against a Postgres database that has no `application_settings` table and assert the table is still absent. GET `/h2-console` on that boot and assert it is not a console page. Run the existing test suite and assert it still uses the in-memory H2 URL.
