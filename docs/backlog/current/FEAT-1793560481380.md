## User story

As an Operator, I want a user email to be a real email address, so a bad address is rejected before it is stored.

Persona: Operator.

## Components

- `krushnatkhawale/study-shield-backend`

## Technical context

`UserRequest` and `AdminUserRequest` mark email `@NotBlank` only. `UserController.create` and `AdminUserController.create` already use `@Valid`, so a format check will return the existing validation error. `AdminPasswordResetRequest` already uses `@Email`. Sign-up still uses `loginId` on `SignUpRequest`; this does not turn that field into an email.

## Acceptance

1. Success: `POST /api/v1/users` and `POST /api/v1/admin-users` with email `not-an-email` return the validation error and store nothing. A normal address still creates the user.
2. Failure: A blank email still fails on the required-field check. A rejected create does not leave a row that can sign in.

## API / data contract impact

None

## Testing requirements

Add a controller or slice test for both create endpoints: `not-an-email` and `""` are rejected, `parent@example.com` is accepted. Assert the user count does not change on the rejected calls.
